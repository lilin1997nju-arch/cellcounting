# 批量会话分组解析

部分设备导出目录不是“一个日期目录对应一个时间点”，而是由 `sessions.idx`
记录每次会话对应的文件夹和板组。解析器按同一 `ReceptacleIdentifier` 分组，
再按采集时间排序，不依赖 XML 中的排列顺序。

例如 QL2603 T6-2 会生成：

| 顺序 | 时间点 | 实际日期 | 文件夹 |
|---:|---|---|---|
| 1 | T0 / Day0 | 2026-06-23 | `2026/06/23/2026-06-23 18-01-39` |
| 2 | T1 / Day1 | 2026-06-24 | `2026/06/24/2026-06-24 17-40-27` |
| 3 | T2 / Day2 | 2026-06-25 | `2026/06/25/2026-06-25 11-26-20` |
| 4 | T3 / Day7 | 2026-06-30 | `2026/06/30/2026-06-30 17-49-34` |
| 5 | T4 / Day14 | 2026-07-07 | `2026/07/07/2026-07-07 15-13-48` |

运行：

```powershell
.venv\Scripts\python.exe -m cellvision parse-sessions `
  --root "E:\CM\20260623 QL2603" `
  --index "E:\CM\20260623 QL2603\sessions.idx" `
  --output "artifacts\ingest\ql2603_sessions.csv"
```

命令会生成：

- `ql2603_sessions.csv`：每次采集一行，包含板组、T序号、Day日期、文件夹路径和96孔图像完整性。
- `ql2603_sessions.groups.csv`：每个板组一行，用于检查板组是否完整。
- `ql2603_sessions.summary.json`：总会话数、板组数和缺失文件夹统计。

`--timepoint-origin 1` 可切换为一基于的 `T1`、`T2`……标签；默认使用模型一致的 `T0`、`T1`……标签。
